**How it works.** It runs in four phases:
1. It reads every remote in every repo without touching the network.
2. It groups the remotes by server and checks each server's homepage once, all at the same time. Any HTTP reply counts as "up", including 404, a redirect, or a TLS handshake with a self-signed certificate.
3. It fetches and inspects the repos in parallel (4 at a time by default). It skips remotes on servers that didn't answer and shows their last-known state instead. If a fetch to an "up" server fails with a network error, later fetches to that server are skipped too.
4. It prints a report and returns an exit code: 0 clean, 1 needs attention, 3 clean as far as known but some remotes weren't fetched.

**Extras I added because they were cheap:**
- **Fuller "uncommitted" check:** stashes count, as do a detached HEAD and a merge or rebase left half-finished.
- **Remotes disagreeing:** it flags when `alpha/main` and `bravo/main` point at different commits.
- **Offline remotes:** shows when the cached copy of the remote last changed.
- **`-e alpha,bravo`:** flags any repo missing one of those remotes.
- **`--no-fetch`:** a fully offline run from what was fetched last time.
- **`-q`:** hides clean repos.
- **`FORCE_COLOR`:** keeps colour when piping to `less -R`, one of the known gotchas.

**Fetching can never touch your work or hang:**
- It only ever runs `git fetch`, with automatic clean-up (gc) and submodule fetching switched off.
- `git status` never locks the repo, so it can't clash with git running in another terminal.
